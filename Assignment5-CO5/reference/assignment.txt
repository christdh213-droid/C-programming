PURPOSE OF THE ASSIGNMENT
Real C programs are built from functions, manage their own memory through pointers, and store data in files. 
Poor choices in these areas lead to programs that are slow, crash, leak memory or lose data.
This assignment investigates a fundamental question:
How should a C programmer divide a program into functions, manage memory and store data so that the 
program stays correct as the data grows?
You are expected to demonstrate the following progression:
Decompose → Design Interfaces → Recurse → Point → Allocate → Persist → Measure → Decide
Simply obtaining a program that runs is not sufficient. Your design reasoning, experimental evidence and 
interpretation are all part of the assessment.
Case Study — District Blood Bank Network
A district has one central blood bank and several hospital storage units. Each donor record holds a donor ID, 
name, blood group, age, phone number and the date of the last donation. Each stock record holds a blood group 
and the number of units available. The blood bank must register donors, find eligible donors of a given group, 
update stock after every donation and issue, and keep all data in files so that nothing is lost when the computer 
is switched off.
