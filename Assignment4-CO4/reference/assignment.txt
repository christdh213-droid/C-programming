TASK 1 – DATA DESIGN REVIEW
Bloom’s Level: K4 – Analyse
Diagnose and Repair a Poor Data Design
6 Marks
A junior developer has written the data part of a primary health centre’s patient register as follows:
char  name[100][20];
int   age[100];
char  phone[100][10];
float bp[100];          /* blood pressure, e.g. 120/80 */
char  visitDate[100][8];
int   count;
void addPatient(char n[], int a, char p[], float b, char d[]) {
    strcpy(name[count], n); age[count] = a; strcpy(phone[count], p);
    bp[count] = b; strcpy(visitDate[count], d); count++;
}
Task 1.1 – Diagnose the Design | 2 Marks
Identify at least five design deficiencies. Do not focus merely on syntax. Examine aspects such as:
Keeping related data in parallel arrays
Storing a phone number of 10 digits in char[10]
Storing blood pressure (two values) in one float
Storing a date as text of 8 characters
Absence of a limit check on count
Use of global variables
Difficulty of sorting patients by age
For each deficiency, explain what could go wrong in the health centre.
Task 1.2 – Repair the Design | 3 Marks
Redesign the data using structures, including nested structures for the date and the blood pressure, and rewrite 
addPatient() to accept a structure pointer.
Task 1.3 – Design Defence | 1 Mark
In not more than 100 words, explain why your structure-based design is easier to sort, pass to functions and 
extend.
Alternative Concept and Complexity Analysis
Your redesign uses an array of structures. The original used parallel arrays (a “structure of arrays”). When could 
parallel arrays still be preferred? Analyse the time to sort n patients (the number of elements moved in each 
swap) and the space used, including padding, in both designs.
Evidence Expected
A reasoned diagnosis, a corrected structure design and a concise justification.

TASK 3 – UNIONS AND MEMORY LAYOUT
Bloom’s Level: K4 – Analyse
Weather-Station Sensor Packets
9 Marks
A weather station sends packets that carry exactly one kind of value: a temperature (float), a humidity 
percentage (int) or a short status text (up to 7 characters). The station has very little memory and stores 
thousands of packets.
Task 3.1 – Structure or Union? | 3 Marks
Design the packet first as a structure containing all three fields, and then as a tagged union (a structure holding a 
type tag and a union). Justify which design suits the station.
Task 3.2 – Predict the Size | 2 Marks
Predict sizeof for each design on a typical 64-bit system, explaining alignment and padding. Then verify with 
sizeof.
Task 3.3 – Implement and Test | 3 Marks
Implement the tagged-union design and a function that prints a packet according to its tag.
Task 3.4 – Misuse Experiment | 1 Mark
Store a temperature and then read the humidity member. Record the output and explain it.

TASK 4 – STRUCTURE FORENSICS
Bloom’s Level: K4 – Analyse
7 Marks
A bank’s savings-account program is supposed to add interest to every account. After running it, every balance 
is unchanged, and one statement does not compile.
struct account { int number; float balance; };
void addInterest(struct account a, float rate) {
    a.balance = a.balance + a.balance * rate / 100;
}
int main(void) {
    struct account list[3] = {{101, 5000}, {102, 12000}, {103, 800}};
    struct account *p = list;
    for (int i = 0; i < 3; i++) addInterest(list[i], 4);
    printf("%d %f\n", p.number, p.balance);
    return 0;
}
Task 4.1 – Locate the Defects | 2 Marks
Identify why the balances do not change and why one statement does not compile.
Task 4.2 – Construct Evidence | 2 Marks
Print the address of the structure inside addInterest() and in main() to prove your explanation of the first defect.
Task 4.3 – Repair the Program | 2 Marks
Correct the program so that interest is added to every account, using a structure pointer and the arrow operator.
Task 4.4 – Prevent Recurrence | 1 Mark
Explain when a structure should be passed by value, by pointer and by const pointer.
Alternative Concept and Complexity Analysis
Instead of passing a pointer, addInterest() could take the structure by value and return the modified copy (list[i] 
= addInterest(list[i], 4)). What would the solution be? Analyse the time to copy sizeof(struct account) bytes 
twice per call against passing one pointer, and the stack space used in each approach.
Evidence Expected
Correct defect identification, address evidence, a repaired program and a guideline for passing structures.

TASK 6 – DESIGN CHALLENGE
Bloom’s Level: K5 – Evaluate
College Canteen Inventory and Billing
13 Marks
The college canteen sells packaged items (with a price and expiry date), cooked items (with a price and the time 
they were prepared) and combo meals (made of up to three other items). It needs to record sales, update stock, 
warn about items expiring within two days, and print the day’s bill summary sorted by revenue.
You are not given the design.
Stage 1 – Interpret the Problem | 2 Marks
Identify the entities, the data of each and the rules. State the requirements as testable statements.
Stage 2 – Propose the Data Model | 2 Marks
Decide where nested structures, arrays of structures and a tagged union (for the three kinds of item) are needed.
Stage 3 – Identify the Critical Design Decisions | 2 Marks
Identify how stock is updated safely, how expiry is checked using a date structure, and which data must be static 
or global.
Stage 4 – Design the Structures and Functions | 4 Marks
Present the structure definitions, the function prototypes using structure pointers, and pseudocode for recording 
a sale and for the expiry warning.
Stage 5 – Implement and Demonstrate | 3 Marks
Implement the program and demonstrate normal sales, a sale that exceeds stock, an expiring item and the sorted 
summary.
Alternative Concept and Complexity Analysis
If the canteen items were kept in a linked list of dynamically allocated structures instead of an array of 
structures, what would the solution be? Analyse the time to add, remove and search an item (O(1), O(n), O(n)
