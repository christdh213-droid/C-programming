Q1 – Precedence, Associativity and the Discount Bug6 Marks
Bloom’s Level: K4 – Analyse
Problem Context – Jan Aushadhi Pharmacy Billing
A government pharmacy computes the amount payable as: price × quantity, less 15% discount for senior citizens, plus 5% 
GST. A developer wrote the whole calculation in one expression without brackets. Customers report wrong amounts.
total = price * qty - price * qty * 15 / 100 * senior + price * qty * 5 / 100;
net   = total > 1000 ? total - 50 : total;   /* Rs 50 off above Rs 1000 */
count = count++ + 1;
Your Challenge
Before running any code:
Predict the value of total and net for three bills of your choice, using the C precedence and associativity rules.
Explain the order in which each operator is applied.
Then write the program, run it and compare. Identify every expression whose result differs from what the pharmacist 
intended, including the effect of integer division.
Inquiry
Explain why the third statement is undefined behaviour in C, and what the compiler does with -Wall.
Design Decision
Rewrite the calculation so that it is correct and readable. Decide whether to use brackets, intermediate variables or both, 
and defend your decision.
Alternative Concept and Complexity Analysis
If the single long expression were replaced by several statements with intermediate variables (gross, discount, tax), what 
would the solution be? Analyse whether the number of operations (time) changes, the extra space used by the temporary 
variables, and the effect on correctness and readability.
Evidence Expected
Predictions before execution, an operator-by-operator explanation, observed outputs, identification of incorrect 
expressions and a corrected, defended calculation.
Q2 – When Does Short-Circuit Evaluation Matter?4 Marks
Bloom’s Level: K4 – Analyse
Problem Context – Railway Senior-Citizen Concession
A ticket counter program grants a concession if the passenger is a senior citizen AND the ticket class is eligible, OR the 
passenger holds a disability card. One check calls a slow function that verifies the card against a server.
Your Challenge
Design experiments to show:
When the second operand of && and of || is not evaluated
How the order of conditions changes the number of calls to the slow verification function
The difference between & and && when used on conditions
Count the number of calls to the slow function for 1,000 sample passengers with different orders of the conditions. Then 
answer:
When should the cheapest or most-likely-false condition be written first, and when is the order irrelevant?
Changed Condition
The verification function now also records every passenger it checks in an audit log. Re-evaluate your recommended 
order.
Alternative Concept and Complexity Analysis
If the combined condition with && and || were replaced by nested if statements, or by the non-short-circuit operators & 
and |, what would the solution be? For n passengers, analyse the number of calls to the slow verification function (time) in 
each version.
Evidence Expected
Designed experiments, call-count evidence, an explanation of short-circuit evaluation and a justified response to the 
changed condition.

Bloom’s Level: K4 – Analyse
Problem Context – University Grade and Scholarship Classifier
The examination cell converts marks to grades (S, A, B, C, D, F) and then decides the scholarship category from the grade 
and family income. Marks outside 0–100 must be rejected.
Your Challenge
Implement the grade decision twice – once with an else–if ladder and once with switch on marks / 10. Determine:
Which input values each version handles correctly and incorrectly (test 100, 90, 89, 0, -1, 101)
The effect of a missing break in the switch version
Why switch cannot directly test ranges such as 75–84
Which version is easier to change when the grade boundaries change

The scholarship rule depends on both the grade and the income band. Decide whether nested if, a switch inside an if, or a

Q6 – Loops That Must Terminate: Loan Repayment Schedule8 Marks
Bloom’s Level: K5 – Evaluate
Problem Context – Self-Help Group Micro-Loan
A women’s self-help group lends money at a monthly interest rate. Each month, interest is added to the outstanding 
balance and the member repays a fixed amount. The program must print the month-by-month schedule until the loan is 
fully repaid, and report the number of months and the total interest paid.
Your Challenge
Design the loop. Determine:
Which loop (for, while or do–while) matches the problem, and why
The exact termination condition, and why balance != 0 is dangerous with floating-point values
What must happen in the last month when the remaining balance is less than the fixed repayment
What happens if the repayment is smaller than the monthly interest
Correctness Check
Create a small loan (for example Rs 10,000 at 2% per month, Rs 2,000 repayment) and calculate the schedule by hand. 
Verify your program against it.
Growth Investigation
Predict and then measure how the number of iterations changes as the repayment amount decreases towards the monthly 
interest.
Deployment Decision
Add a safety limit (for example 360 months) using break, and decide what message the program should give when the 
limit is reached. Defend your decision.
Alternative Concept and Complexity Analysis
If the number of months were calculated directly from the loan formula n = −log(1 − r·P / E) / log(1 + r), instead of 
simulating every month in a loop, what would the solution be? Analyse the time (O(1) versus O(n) iterations), the space, 
and the precision problems of each approach.
Evidence Expected
A justified loop design, a hand-verified schedule, iteration counts, protection against non-terminating loops and an 
evidence-based deployment decision.
